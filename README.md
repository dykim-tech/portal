# DYKIM PORTAL

개인 PC 또는 사내 서버에서 운영하는 설치·자료·자산 통합 포털입니다. Node.js 24와 SQLite로 동작합니다.

[포털 설계도: 구조·데이터 저장 위치·GitHub 역할](docs/PORTAL_DESIGN.md) · [기동 및 장애 대응 절차](docs/OPERATIONS.md) · [PC 교체·이전 가이드](docs/PC_MIGRATION.md)

## 메뉴와 기능

| 메뉴 | 기능 |
|---|---|
| 대시보드 | 설치·자료·자산 수, 최근 업데이트, 7일 이내 및 경과한 관리 기한 |
| 설치관리 | 분류 선택 없이 설치 정보 등록·검색, 고객사·제품명·세부내용 클릭으로 수정, 설치 건별 자료 첨부·미리보기·다운로드 |
| 자료 관리 | 대분류→중분류→소분류 및 하위 폴더의 탐색기형 화면, 폴더별 자료 등록·검색·다운로드·미리보기, 폴더와 자료 수정·이동 |
| 자산 관리 | 대분류→중분류→소분류, 일반 비품·IT 장비 등록·검색, 건별 첨부자료·변경 이력·관리 기한 |
| 업무관리 | 고객 등록, 고객별 업무일지(날짜·제목·업무 유형·담당자·상태·내용) 작성·검색 |
| 리포트 | 설치·자료·자산·업무 현황, 기간별 조회, 엑셀용 CSV 내려받기 |
| 사용자 관리 | 관리자·편집자·조회자, 사용자 추가·수정·비활성화·비밀번호 재설정 |
| 백업/복구 | 관리자가 온라인 백업 생성·목록 조회·다운로드, 선택한 백업 시점으로 복구 |
| 설정 | 일반 모드·다크 모드, 내 비밀번호 변경 |

상단의 **기한 알림**에서 예정·당일·경과 알림과 읽음 상태를 관리합니다. 관리자만 사용자 관리 메뉴에 접근할 수 있습니다. 모든 활성 사용자는 동일한 설치·자료·자산 목록을 공유합니다.

## 개인 PC에서 실행

Node.js **24.13 이상 24.x**가 필요합니다.

```powershell
git clone https://github.com/dykim-tech/portal.git
cd portal
npm ci
Copy-Item .env.example .env
npm start
```

[http://localhost:3000](http://localhost:3000)에 접속합니다. 최초 실행 시 **첫 관리자 만들기** 화면에 아래 코드와 관리자 이름, 로그인 아이디, 이메일, 비밀번호(12자 이상)를 입력합니다. 이후 로그인에는 이메일 대신 **아이디**를 사용합니다.

```powershell
Get-Content .\data\setup-token.txt
```

Linux는 `cat data/setup-token.txt`를 사용합니다. 코드 파일은 관리자 생성 후 자동 삭제됩니다. 기본 계정·공유 비밀번호는 없습니다. 기존 사용자는 관리자가 사용자 관리 메뉴에서 추가합니다.

기존 이메일 로그인 계정의 아이디는 업데이트 시 이메일의 `@` 앞부분으로 자동 지정됩니다. 같은 앞부분이 여러 계정에 있으면 뒤에 `-2`, `-3` 등이 붙습니다. **사용자 관리**에서 각 계정의 아이디를 확인·변경할 수 있으며 기존 비밀번호는 유지됩니다.

접속 주소는 `.env`의 `APP_ORIGIN`과 정확히 같아야 합니다. 예를 들어 localhost 대신 127.0.0.1로 접속하면 쓰기 요청이 차단됩니다. 수동으로 `npm start`를 실행한 경우에는 명령 창을 닫으면 포털도 중지됩니다. Windows 자동 실행 설정은 아래 절차를 사용합니다.

## Windows에서 PowerShell 없이 자동 실행

포털을 실행 중인 PowerShell 창에서 **Ctrl+C**로 수동 서버를 먼저 중지합니다. 설치 작업은 한 번만 필요합니다.

```powershell
Set-Location 'F:\ChatGPT\DYKIM-PORTAL'
git pull --ff-only
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\windows-install.ps1
```

설치가 성공하면 `Portal is running in the background at http://localhost:3000`이 출력됩니다. 그 뒤 PowerShell 창을 닫아도 포털이 유지되고, Windows에 다시 로그인하면 자동으로 시작합니다. 작업 이름은 **DYKIM Personal Portal**입니다. 기존 예약 작업이 있으면 설치 스크립트가 중지하고 콘솔 창 없는 작업으로 교체합니다. PC 전원이 꺼지면 접속할 수 없습니다.

설치 스크립트는 현재 사용자 권한으로 Node 서버를 직접 작업 스케줄러에 등록하고 즉시 실행합니다. 같은 실행 경로의 작업이 이미 있으면 재등록하지 않고 재시작합니다. 새 작업 등록이나 작업 설정 변경에는 Windows 관리자 권한이 필요할 수 있습니다. 기존 예약 작업이 남긴 서버 프로세스가 있으면 확인 후 종료합니다. 비밀번호를 스크립트에 저장하거나 시스템 전체의 실행 정책을 변경하지 않습니다. 이 비대화형 실행 방식은 네트워크 공유 드라이브나 Windows 암호화 파일에 접근할 수 없으므로 포털 폴더와 `data/`는 로컬 디스크에 두세요. 앱의 기존 `data/`와 `.env`를 계속 사용합니다. 서버 실행 기록은 `data/server.log`에 저장됩니다.

실패하면 작업 스케줄러에서 **DYKIM Personal Portal**의 상태를 확인하고 `data/server.log`의 마지막 부분을 읽으세요. 수동으로 다시 시작할 때는 작업 스케줄러의 **실행**을 누르거나 `Start-ScheduledTask -TaskName 'DYKIM Personal Portal'`을 실행하면 됩니다. 포털 파일을 업데이트할 때는 먼저 스케줄러에서 작업을 **끝내기**로 중지하고 업데이트한 다음 작업을 다시 시작합니다.

## 자료 관리와 미리보기

- 전체 자료에서 **대분류**, 그 아래에 **중분류**를 만듭니다. 중분류를 선택하면 **소분류**를 추가할 수 있으며, 이후에도 현재 폴더 아래에 하위 폴더를 계속 만들 수 있습니다. 자료 등록은 중분류와 그 아래 폴더에서 사용합니다.
- 폴더의 **이름 변경**, 자료의 **수정**으로 이름과 소속 폴더를 바꿀 수 있습니다. 파일 확장자와 본문은 유지됩니다.
- 자료 파일을 우클릭해 **이동**을 누른 뒤 등록된 다른 폴더를 선택하면 파일을 옮길 수 있습니다. 이동 후 새 위치가 열립니다.
- 과거 버전에서 이미 `VPN · 연결`처럼 한 폴더 이름으로 합쳐진 분류는 그대로 유지됩니다. 새 버전은 기존 폴더를 더 이상 합치지 않으며, 새 하위 폴더도 재시작 후 유지됩니다.
- 파일명 클릭 시 미리보기를 엽니다. 현재 폴더 내 이름 검색, 열 제목 클릭 정렬, 페이지당 25·50·70·100건 선택을 지원합니다. 폴더는 파일보다 먼저 표시됩니다.
- PDF, PNG, JPG, GIF, WebP, UTF-8 텍스트(TXT/MD/CSV/LOG)를 미리 볼 수 있습니다.
- DOCX/XLSX/PPTX/HWP 등은 다운로드하여 해당 프로그램에서 엽니다. 브라우저가 PDF 미리보기를 지원하지 않을 때도 다운로드를 사용하세요.
- 파일당 최대 500MB입니다. 업로드 중 임시 파일을 로컬 `data/upload-tmp/`에 저장하고 SQLite에 작은 조각으로 기록합니다. 파일이 커질수록 업로드·백업에 필요한 디스크 공간과 시간이 늘어납니다.
- 비어 있는 폴더만 삭제할 수 있습니다. 기존 자료와 폴더는 업데이트 시 그대로 유지됩니다.
- 자료 이름과 소속 폴더는 변경할 수 있습니다. Office/HWP 변환 미리보기는 현재 범위에 포함하지 않습니다.

## 설치 등록·자산 분류와 첨부자료

설치관리는 분류를 선택하지 않고 **설치 정보 등록** 버튼에서 바로 입력합니다. 기존 설치 기록과 첨부파일은 그대로 유지되며, 과거 분류 정보는 데이터에 남아 있어도 설치관리 화면에서는 표시·수정하지 않습니다.

자산관리의 왼쪽에서는 대분류를 만들고, 선택한 분류 아래에 중분류·소분류를 차례로 만듭니다. 자산을 등록할 때 소분류를 선택하며 상위 분류를 클릭하면 그 아래 자산까지 함께 조회합니다. 기존 자산 기록은 **미분류**로 남아 있고 수정 화면에서 소분류를 지정할 수 있습니다.

설치 정보는 참고 표의 **구분·고객사·제품명·세부내용·수량·설치시작일·설치종료일·담당자·설치엔지니어·비고** 순서로 표시됩니다. 구분은 목록 번호이며, 설치종료일은 진행 중인 설치라면 비워 둘 수 있습니다. 기존 설치 기록의 수량은 1로 표시되고 기존 날짜와 메모는 유지됩니다. 등록·수정 화면에서 상태와 설치 위치도 계속 관리할 수 있습니다.

설치 표의 고객사·제품명·세부내용을 누르면 해당 설치정보의 수정 창이 열립니다. 설치·자료·자산·업무일지·사용자 목록에서는 열 제목을 눌러 정렬하고 페이지당 25·50·70·100건을 선택할 수 있습니다. 표시 건수 선택은 해당 브라우저에 저장됩니다.

등록된 고객, 업무일지, 설치정보, 자산, 자산 분류, 자료 폴더·파일, 사용자를 마우스 오른쪽 버튼으로 누르면 **수정·삭제** 메뉴가 열립니다. 대시보드의 설치정보·자산과 기한 알림의 자산에도 같은 메뉴를 사용할 수 있습니다. 수정 권한이 없는 계정에는 이 메뉴가 표시되지 않습니다.

우클릭 메뉴에서 **삭제**를 누르면 여러 항목 선택 화면으로 전환됩니다. 처음 누른 항목이 선택된 상태로 시작하며, 체크박스로 다른 항목을 고르거나 **현재 목록 모두 선택**을 사용할 수 있습니다. 다른 페이지로 이동해도 선택은 유지됩니다. **선택한 N개 삭제**를 누르면 한 번 확인한 뒤 순서대로 처리하고, 삭제할 수 없는 항목은 화면에 실패 이유와 함께 남깁니다. 고객에 연결된 설치정보·업무일지는 고객 목록 삭제 후에도 보존됩니다.

설치 정보와 자산 정보에는 파일당 최대 500MB의 자료를 첨부할 수 있습니다. 기존 건당 50MB 합계 제한은 제거했습니다. PDF·이미지·텍스트는 미리 볼 수 있고 다른 형식은 다운로드합니다.

## 업무관리와 리포트

설치 정보에 이미 등록된 고객명은 업무관리의 고객 목록에 자동으로 추가됩니다. 새 고객을 직접 등록한 뒤 업무일지를 작성할 수도 있습니다. 업무일지는 고객·날짜·제목·업무 유형·담당자·진행 상태·내용을 저장하며 고객, 날짜, 유형, 상태, 검색어로 조회합니다. 업무 유형은 **정기점검 / 장애지원 / 설치 / Per Call / 기타** 중 선택합니다. 이전에 등록한 업무일지는 유형을 임의 지정하지 않고 **미분류**로 표시하며, 수정 시 유형을 선택할 수 있습니다. CSV 리포트에도 유형이 포함됩니다.

리포트에서 조회 시작일·종료일을 선택하면 설치·자료·자산·업무일지 건수와 상태·분류·고객별 현황을 볼 수 있습니다. 각 자료의 CSV는 엑셀에서 열 수 있는 UTF-8 형식이며, 화면에서 선택한 기간이 반영됩니다. 자산과 자료의 기간 기준은 최근 수정일과 등록일의 한국 표준시 날짜입니다.

## 기한 알림

자산의 **관리 기한**에 점검·보증·반납 등 필요한 날짜를 지정합니다. **사전 알림**이 7이면 7일 전부터, 0이면 당일부터 알립니다.

서버 실행 중 매분 한국 표준시 기준으로 확인합니다. 사전/당일/경과 단계별로 자산·기한·사용자당 한 번 생성되어 중복을 막습니다. 서버가 꺼진 동안의 기한은 다음 실행 시 현재 상태로 확인합니다. 기한 변경/해제 또는 사용 종료 시 기존 알림은 제거됩니다. 알림은 포털 내부에 제공되며 이메일·문자·브라우저 푸시는 포함하지 않습니다.

## 권한과 로그인

- 관리자: 사용자·설치·자료·자산 관리
- 편집자: 설치·자료·자산·고객·업무일지 등록/수정, 분류 관리, 자료 삭제
- 조회자: 열람·검색·다운로드·리포트 확인·알림 확인

12시간 세션, HttpOnly/SameSite 쿠키, 서버 권한 검사, 출처 검사, 로그인 시도 제한, scrypt 비밀번호 해시를 사용합니다. 비밀번호/권한 변경 또는 비활성화 시 기존 로그인은 해제됩니다. 관리자는 본인의 관리자 권한을 해제하거나 자신을 비활성화할 수 없습니다. 자산·설치 동시 수정 충돌은 덮어쓰지 않고 최신 자료 재확인을 안내합니다.

## Docker

```sh
docker compose up -d --build
docker compose exec portal cat /app/data/setup-token.txt
```

localhost:3000에 열리며 계정과 모든 자료는 `portal_data` 볼륨, 백업은 `portal_backups` 볼륨에 저장됩니다. `docker compose down -v`는 데이터 볼륨을 삭제하므로 사용하지 마세요.

## 사내 서버 운영

HTTPS 역방향 프록시(Caddy 등)를 사용하고 `deploy/Caddyfile.example`의 도메인을 수정하세요. 아래 값을 `.env`에 설정합니다.

```dotenv
HOST=127.0.0.1
PORT=3000
APP_ORIGIN=https://portal.example.com
COOKIE_SECURE=true
TRUST_PROXY=true
NODE_ENV=production
DATA_DIR=./data
```

`TRUST_PROXY=true`는 직접 관리하는 단일 프록시 뒤에서만 사용합니다. 실제 도메인과 HTTPS 인증서를 준비하고 외부 포트는 프록시에만 열어 주세요. Docker는 내부 HOST=0.0.0.0을 유지하며 호스트 포트는 127.0.0.1에 연결합니다. 변경 후 `docker compose up -d --build`로 적용합니다.

Linux 서비스 예시는 `deploy/portal.service`입니다. 전용 portal 계정, `/opt/portal` 설치 경로, 쓰기 가능한 data/backups 폴더를 먼저 준비하고 Node 경로를 확인하세요. Windows 상시 운영은 조직의 Windows 서비스 운영 방식이나 Docker 재시작 정책을 적용하세요. 방화벽·DNS·인증서·자동 시작 설정은 이 코드가 자동 변경하지 않습니다.

## 백업과 복구

```sh
npm run backup
# Docker
docker compose exec portal npm run backup
```

관리자는 포털의 **백업/복구** 메뉴에서 **지금 백업**을 눌러 온라인 백업을 만들고, 저장된 백업 목록의 시점·크기를 확인하고 파일을 다운로드할 수 있습니다. 명령줄의 `npm run backup`도 같은 `backups/` 폴더에 저장합니다. 백업에는 계정·자산·설치·자료·고객·업무일지·분류·이력과 첨부파일 조각이 들어 있습니다. 계정 해시와 업무자료가 포함되므로 다운로드 파일의 접근을 제한하세요.

**복구**에서 목록의 백업 시점을 선택하면 포털이 새 요청을 잠시 멈추고 복구 직전 상태를 `portal-pre-restore-*.sqlite`로 백업한 뒤 선택한 파일을 적용하고 다시 연결합니다. 선택한 시점 이후의 입력은 현재 화면에서 사라지며, 복구 후 다시 로그인해야 할 수 있습니다. 백업 파일이 클수록 복구와 재연결에 시간이 걸리고, 임시 사본을 위한 추가 디스크 공간이 필요합니다. 화면 복구를 사용할 수 없는 경우의 수동 절차는 [운영 문서](docs/OPERATIONS.md)에 있습니다. 과거 `portal.sqlite-wal`, `portal.sqlite-shm`과 백업 파일을 섞지 마세요.

고객·업무일지 기능 이전에 만든 초기 백업도 확인된 포털 형식이라면 화면에서 복구할 수 있습니다. 서버는 선택한 원본을 수정하지 않고 임시 사본을 현재 형식으로 이전한 뒤 무결성과 주요 데이터 보존을 검사합니다. 형식이 다르거나 검사에 실패한 파일은 적용하지 않습니다. 이 경우 [운영 문서](docs/OPERATIONS.md)의 점검 절차를 확인하세요. `.env`의 `BACKUP_DIR`을 설정하면 백업 폴더를 바꿀 수 있습니다.

## 검사·업데이트·GitHub

```sh
npm run check
npm test
npm audit --omit=dev
```

테스트는 운영 데이터와 분리한 임시 DB를 사용합니다. GitHub Actions에서도 같은 검사를 실행합니다. 업데이트는 백업 → 서버 중지 → `git pull --ff-only` → `npm ci` → 검사 → 재시작 순서입니다.

`.env`, `data/`, `backups/`, `work/`, `node_modules/`는 Git에서 제외됩니다. 자료와 계정은 GitHub에 전송하지 않습니다. 일반/다크 모드만 브라우저 localStorage에 저장하고 나머지 업무자료는 서버 DB에 보관합니다.

단일 서버·소규모 공유 환경용입니다. SQLite 파일은 로컬 디스크에 보관하세요. 다중 서버 운영, 그룹별 자료 분리, 자동 이메일 비밀번호 복구, 다중 인증은 현재 포함하지 않습니다.
