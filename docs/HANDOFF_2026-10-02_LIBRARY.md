## 2. 사용자 이용 방법

### 분류 생성 및 자료 등록

1. 왼쪽 메뉴에서 **자료 관리**를 선택한다.
2. **전체 자료**에서 **대분류 등록**을 선택한다.
3. 생성한 대분류를 선택하고 **중분류 등록**을 선택한다.
4. 중분류를 선택한 뒤 **자료 등록**으로 파일을 업로드한다.

- 중분류 아래에는 추가 분류를 만들 수 없다.
- 파일당 최대 500MB까지 등록할 수 있다.
- PDF, PNG, JPG, GIF, WebP, 텍스트는 지원 조건에 따라 미리보기 가능하다.
- Office·HWP 등 그 외 형식은 다운로드 후 해당 프로그램에서 확인한다.

### 이름 변경 및 자료 수정

- 분류 목록의 **이름 변경**, 또는 분류를 선택한 화면 위쪽의 **분류 이름 변경**으로 분류명을 변경한다.
- 자료 목록의 **수정**으로 자료명과 소속 중분류를 변경한다.
- 저장 후 이동한 분류의 목록을 표시하며 검색 조건과 페이지를 초기화한다.
- 파일 확장자는 변경할 수 없다. 파일 본문 교체나 문서 내용 편집은 이번 구현에 포함하지 않았다.
- 관리자와 편집자는 수정할 수 있으며, 조회자는 수정할 수 없다.
- 기존에 전체 자료 또는 대분류에 직접 등록되어 있던 자료는 계속 열람할 수 있다. 자료 수정 시 현재 위치를 유지하거나 중분류로 옮길 수 있다.

## 3. 기존 소분류 전환 방식

새 코드를 사용하여 서버가 시작될 때 기존 3단계 이상 분류를 2단계로 전환한다.

```text
변경 전
FortiGate
└─ VPN
   └─ StrongSwan(Ubuntu) 연결
      └─ 등록 자료

변경 후
FortiGate
├─ VPN
└─ VPN · StrongSwan(Ubuntu) 연결
   └─ 등록 자료
```

- 이전 중분류와 소분류 이름을 ` · `로 연결하여 새 중분류 이름으로 사용한다.
- 기존 중분류도 유지한다. 폴더나 자료를 삭제하지 않는다.
- 기존 폴더 ID를 유지하고 상위 폴더 및 이름만 변경하므로 자료 연결이 유지된다.
- 이름이 겹치면 ` (2)`, ` (3)` 등의 번호를 붙인다.
- 전환된 이름은 100자 이내로 제한되므로 긴 경로는 잘릴 수 있다. 원래 명칭 확인이 필요할 경우를 위해 적용 전 백업을 권장한다.
- 전환은 하나의 트랜잭션으로 수행한다. 다시 시작해도 이미 2단계인 분류는 재변환하지 않는다.
- 운영 데이터에 실제 전환이 적용되었는지는 이번 대화에서 확인하지 않았다.

## 4. 적용 전 백업

PowerShell에서 다음을 실행한다.

```powershell
Set-Location -LiteralPath 'F:\ChatGPT\DYKIM-PORTAL'
npm run backup
```

프로젝트의 `backups` 폴더에 날짜가 포함된 SQLite 백업 파일이 생성된다. 현재 구현은 SQLite 온라인 백업을 사용하므로 서버 실행 중에도 백업할 수 있다. 계정·분류·자료와 첨부파일 내용을 포함한다.

기본 데이터베이스 위치는 `data\portal.sqlite`이며, `.env`의 `DATA_DIR` 설정이 있으면 해당 경로를 사용한다. 백업 완료 메시지와 생성 파일을 확인한 후 재시작한다.

## 5. 서버 재시작 및 화면 반영

프로젝트에는 Windows 예약 작업을 통한 자동 실행 방식이 준비되어 있다. 실제 실행 방식에 맞는 절차 하나를 사용한다. 자동 실행 서버가 실행 중인 상태에서 별도로 `npm start`를 실행하면 포트 충돌이 발생할 수 있다.

### Windows 자동 실행으로 운영하는 경우

1. Windows 시작 메뉴에서 **작업 스케줄러**를 검색하여 연다.
2. **작업 스케줄러 라이브러리**에서 **DYKIM Personal Portal**을 찾는다.
3. 해당 작업을 우클릭하여 **끝내기**를 선택한다.
4. 작업이 중지된 것을 확인한 뒤 우클릭하여 **실행**을 선택한다.
5. 포털 접속 후 **Ctrl + F5**로 새로고침한다.

PowerShell을 사용할 경우:

```powershell
Stop-ScheduledTask -TaskName 'DYKIM Personal Portal'
Start-Sleep -Seconds 2
Get-ScheduledTask -TaskName 'DYKIM Personal Portal' | Select-Object TaskName, State
```

작업이 `Running` 상태가 아닌 것을 확인한 후 실행한다.

```powershell
Start-ScheduledTask -TaskName 'DYKIM Personal Portal'
```

### 명령 창에서 수동 실행하는 경우

기존 서버가 실행 중인 창에서 **Ctrl + C**를 누르고 종료를 확인한 후 실행한다.

```powershell
Set-Location -LiteralPath 'F:\ChatGPT\DYKIM-PORTAL'
npm start
```

수동 실행은 명령 창을 닫으면 서버도 종료되므로 창을 유지한다.

### 재시작 확인 및 문제 확인

- 기본 접속 주소: `http://localhost:3000`
- 실제 접속 주소는 `.env`의 `APP_ORIGIN` 설정과 일치해야 한다.
- 예약 작업 상태와 로그를 확인한다.

```powershell
Get-ScheduledTask -TaskName 'DYKIM Personal Portal' | Select-Object TaskName, State
Get-Content -LiteralPath 'F:\ChatGPT\DYKIM-PORTAL\data\server.log' -Tail 60
```

예약 작업 방식의 로그는 `data\server.log`에 기록된다. `npm start`로 실행했다면 해당 명령 창의 출력을 확인한다. 포트 충돌이 발생하면 기존 실행 상태부터 확인하며, 다른 프로그램의 프로세스를 임의로 종료하지 않는다.

## 9. 복구 시 참고

기존 소분류의 2단계 전환은 서버 시작 시 데이터베이스에 저장된다. 코드만 이전 버전으로 바꿔도 원래 3단계 구조가 자동 복원되지는 않는다.

전환 전 구조로 복구해야 한다면 서버를 완전히 중지하고 현재 데이터 폴더를 별도로 보관한 뒤, 전환 전 백업과 대응하는 코드를 함께 복원한다. 백업 이후 등록·수정한 내용은 별도 보존하지 않으면 복구본에 포함되지 않는다. 과거 `portal.sqlite-wal`·`portal.sqlite-shm`을 복원할 백업 파일과 섞지 않는다.

기존 운영·이관 문서는 `docs/OPERATIONS.md`, `docs/PC_MIGRATION.md`, `README.md`를 참고한다.
