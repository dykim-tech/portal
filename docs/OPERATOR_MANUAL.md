# DYKIM PORTAL 운영자 매뉴얼

> 기준: 2026-10-05. 대상: `F:\ChatGPT\DYKIM-PORTAL`에 설치해 Windows 작업 스케줄러(`DYKIM Personal Portal`)로 운영하는 포털의 관리자. 자세한 구조는 설계도, 화면 기준은 화면 디자인 문서를 함께 확인합니다.

## 1. 운영 구성 요약

| 항목 | 내용 |
|---|---|
| 접속 주소 | http://localhost:3000 (포털을 실행하는 PC에서만 접속) |
| 자동 실행 | Windows 작업 스케줄러의 `DYKIM Personal Portal` 작업. 해당 Windows 사용자가 로그인할 때 실행 |
| 서버 | Node.js 24.13 이상 24.x가 `server/windows-start.mjs` → `server/index.mjs` 실행 |
| 운영 데이터 | `data\portal.sqlite` (계정·설치·자료·자산·업무일지·첨부파일 모두 포함) |
| 실행 로그 | `data\server.log` |
| 백업 | `backups\portal-날짜.sqlite` (생성 후 3일이 지나면 자동 삭제) |
| 설정 | 프로젝트 폴더의 `.env` (없으면 기본값 사용) |

- PC가 꺼져 있거나 해당 Windows 사용자가 로그인하지 않으면 포털에 접속할 수 없습니다.
- `data\`, `backups\`, `.env`는 GitHub에 저장되지 않습니다. 운영 데이터는 반드시 백업 파일로 별도 보관합니다.

## 2. 서비스 기동 절차

### 2-1. 평상시 자동 기동

1. PC를 켜고 포털을 설치한 Windows 사용자로 로그인합니다.
2. 예약 작업이 서버를 자동으로 시작합니다. PowerShell 창을 열어 둘 필요가 없습니다.
3. 브라우저에서 http://localhost:3000 에 접속해 로그인합니다.

### 2-2. 상태 확인

PowerShell에서 실행합니다.

```powershell
Get-ScheduledTask -TaskName 'DYKIM Personal Portal' | Select-Object TaskName,State
Get-ScheduledTaskInfo -TaskName 'DYKIM Personal Portal' | Select-Object LastRunTime,LastTaskResult
Invoke-RestMethod 'http://127.0.0.1:3000/api/health'
```

- 정상: 작업 상태 `Running`, health 응답에 `ok: true`, `database: ok`. `database: error`이면 DB를 읽지 못하는 상태이며, 3분 동안 계속되면 포털이 스스로 다시 시작합니다. 포털이 10분 안에 5번 넘게 멈추면 5분 쉬었다가 계속 다시 시도합니다(`data\server.log`에 `failed repeatedly` 기록).
- health의 `ok: true`는 웹 서버 응답만 뜻합니다. 로그인 오류가 나면 `data\server.log`도 함께 확인합니다.
- 화면이 예전 모습이면 브라우저에서 **Ctrl + F5**로 강력 새로고침합니다.

### 2-3. 수동 시작

예약 작업이 `Ready` 또는 중지 상태일 때 실행합니다.

```powershell
Start-ScheduledTask -TaskName 'DYKIM Personal Portal'
Start-Sleep -Seconds 3
Invoke-RestMethod 'http://127.0.0.1:3000/api/health'
```

작업 스케줄러 화면을 쓸 경우: 시작 메뉴에서 **작업 스케줄러** → **작업 스케줄러 라이브러리** → **DYKIM Personal Portal** 우클릭 → **실행**.

### 2-4. 재시작 (서버 코드 변경 후, 응답이 없을 때)

1. 먼저 6장의 방법으로 백업을 만듭니다.
2. 아래 명령으로 중지 후 다시 시작합니다.

```powershell
Stop-ScheduledTask -TaskName 'DYKIM Personal Portal'
Start-Sleep -Seconds 3
Get-NetTCPConnection -LocalPort 3000 -State Listen -ErrorAction SilentlyContinue
Start-ScheduledTask -TaskName 'DYKIM Personal Portal'
Start-Sleep -Seconds 3
Invoke-RestMethod 'http://127.0.0.1:3000/api/health'
```

- 중지 후 포트 3000을 듣는 프로세스가 남아 있으면 8장 B 절차로 먼저 확인합니다.
- 화면 파일(`public\`)만 바뀐 경우에는 재시작 없이 **Ctrl + F5**로 반영됩니다. 문서(`docs\`) 수정도 운영관리 화면을 다시 열면 반영됩니다.

### 2-5. 중지

```powershell
Stop-ScheduledTask -TaskName 'DYKIM Personal Portal'
```

중지하면 다음 Windows 로그인 또는 수동 시작 전까지 포털에 접속할 수 없습니다. 자동 시작까지 막으려면 `Disable-ScheduledTask -TaskName 'DYKIM Personal Portal'`을 사용하고, 다시 쓸 때 `Enable-ScheduledTask`로 해제합니다.

### 2-6. 명령 창에서 수동 실행 (예약 작업을 쓰지 않을 때만)

```powershell
Set-Location 'F:\ChatGPT\DYKIM-PORTAL'
npm.cmd start
```

- 예약 작업 서버가 실행 중일 때 함께 실행하면 포트 3000 충돌이 납니다.
- 명령 창을 닫으면 서버도 종료됩니다. 종료는 **Ctrl + C**.

### 2-7. 예약 작업이 없거나 손상된 경우 (재등록)

```powershell
Set-Location 'F:\ChatGPT\DYKIM-PORTAL'
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File '.\scripts\windows-install.ps1'
```

성공하면 `Portal is running in the background at http://localhost:3000`이 표시됩니다. 작업 등록·설정 변경에는 Windows 관리자 권한이 필요할 수 있습니다.

## 3. 접속과 로그인

- 로그인은 이메일이 아닌 **아이디**로 합니다.
- 최초 실행 시에만 **첫 관리자 만들기** 화면이 나옵니다. 설정 코드는 `Get-Content .\data\setup-token.txt`로 확인하며 관리자 생성 후 자동 삭제됩니다.
- 운영 중에 첫 관리자 화면이 다시 나오거나 자료가 모두 비어 보이면 **새 계정이나 자료를 입력하지 말고** 8장 D 절차를 따릅니다.
- 접속 주소는 `.env`의 `APP_ORIGIN`과 같아야 합니다(기본 `http://localhost:3000`). `127.0.0.1`로 접속하면 저장 요청이 차단됩니다.
- 로그인 유지 시간은 12시간입니다. 비밀번호·권한 변경이나 비활성화 시 기존 로그인은 해제됩니다.

## 4. 메뉴별 사용법

### 4-1. 화면 구성과 공통 기능

- 왼쪽 세로 메뉴와 상단 가로 메뉴는 같은 화면으로 이동합니다. 왼쪽 메뉴 아래의 **운영관리**, **사용량 관리** 링크는 관리자에게만 보입니다.
- 상단 **뒤로가기**·브라우저 뒤로가기: 직전에 열었던 화면으로 이동하며 대시보드에서 멈춥니다(포털 밖으로 나가지 않음). 창이 열려 있으면 창만 닫습니다. 포털을 연 직후 아무것도 누르지 않은 상태에서는 브라우저가 이전 사이트로 나갈 수 있습니다.
- 상단 **알림**: 자산 관리 기한(사전·당일·경과)과 관리자용 업무 활동 알림을 확인합니다. 읽음 버튼은 해당 알림 한 건에만 적용됩니다.
- 목록 표: 열 제목을 눌러 정렬하고, 페이지당 25·50·70·100건을 고릅니다.
- 열 너비: 표 머리글 사이 경계를 마우스로 끌어 조정합니다. 경계를 두 번 누르면 기본 너비로 돌아갑니다. 너비는 브라우저에 저장됩니다.
- 우클릭 메뉴: 수정 권한이 있으면 항목을 우클릭해 **수정·삭제**를 엽니다. 삭제는 여러 항목 선택 화면으로 바뀌며, **선택한 N개 삭제**에서 한 번 확인한 뒤 처리합니다.

### 4-2. 대시보드

- 건수 카드: 등록 자산·설치 정보·등록 자료·읽지 않은 알림.
- **저장소 사용량**(관리자): 드라이브 사용률(90% 이상이면 경고색)·여유 공간, 포털 데이터·첨부파일·백업 폴더 합계.
- **오늘의 할 일 · 미완료**: 내 TO-DO 메모 중 완료하지 않은 항목(최대 10건). 누르면 TO-DO List로 이동합니다.
- **최근 프로젝트**: 최근 수정한 프로젝트 3건. 누르면 프로젝트 상세 창이 열립니다.
- 최근 일주일 업무관리, 최근 설치 정보, 최근 업데이트한 자산.

### 4-3. 설치관리

1. **설치 정보 등록**을 누릅니다.
2. 고객사·제품명·세부내용·수량·설치시작일(필수)·설치종료일·담당자·설치엔지니어·비고를 입력하고 저장합니다.
3. 저장 후 열리는 상세 창에서 첨부파일을 추가합니다.

- 목록의 고객사·제품명·세부내용을 누르면 상세·수정 창이 열립니다.
- 설치종료일은 진행 중이면 비워 둡니다. 설치 정보의 고객사는 업무관리 고객 목록에도 자동으로 추가됩니다.

### 4-4. 프로젝트 관리

- **프로젝트 등록**: 유형(설치/기타), 단계(설치 전·중·후), 상태(예정·진행 중·보류·완료), 고객사, 담당자, 위치, 예정·실제 일정, 메모를 입력합니다.
- 설치 프로젝트는 단계별 기본 할 일이 만들어지며, 목록에서 프로젝트를 다시 열어 할 일을 추가·완료합니다.
- 기존 설치 정보를 연결할 수 있습니다. 프로젝트를 삭제해도 연결된 설치 기록은 유지됩니다.

### 4-5. 자료 관리

- 폴더: 빈 공간을 우클릭해 **폴더 생성**을 누르면 현재 위치, 폴더를 우클릭해 **하위 폴더 생성**을 누르면 그 폴더 안에 하위 폴더를 만듭니다. 단계 제한은 없습니다.
- 폴더 트리: 하위 폴더는 오른쪽으로 들여써지고 안내선이 표시됩니다. 화살표로 펼치기·접기, 이름을 눌러 이동합니다.
- 폴더 트리 너비: 트리와 목록 사이 경계를 마우스로 끌어 조정하고, 두 번 누르면 기본 너비로 돌아갑니다.
- 자료 등록: **자료 등록** 버튼, 또는 파일을 끌어 놓기.
  - 오른쪽 자료 영역에 놓으면 현재 폴더에 등록됩니다.
  - 왼쪽 트리나 목록의 폴더 위에 놓으면 그 폴더에 등록되고 그 폴더가 열립니다.
  - 여러 파일을 한 번에 놓을 수 있습니다.
- 폴더째 등록: PC의 폴더를 끌어 놓거나 우클릭 메뉴의 **폴더 업로드**로 폴더를 고르면, 하위 폴더 구조를 그대로 만들고 파일을 각 폴더에 등록합니다.
  - 같은 이름의 폴더가 이미 있으면 새로 만들지 않고 그 폴더에 합쳐 넣습니다.
  - 같은 폴더에 이름과 크기가 같은 파일이 이미 있으면 건너뜁니다(같은 폴더를 다시 올려도 중복되지 않음).
  - 끌어 놓기는 빈 폴더도 만들지만, **폴더 업로드**(폴더 선택 창)는 브라우저 특성상 빈 폴더를 전달하지 않습니다.
  - 끌어 놓기로 폴더를 올리는 것은 자료 관리에서만 됩니다. TO-DO·업무관리 첨부에 놓은 폴더는 제외됩니다.
- 파일 크기 제한은 없습니다. 디스크 여유 공간이 실제 한도이므로 큰 파일은 9장을 참고합니다.
- Google Drive로 복사: 이 PC의 Google Drive 데스크톱 앱(G:\내 드라이브)을 이용합니다. Chrome 또는 Edge에서 사용합니다.
  1. 자료 관리 위쪽 **Drive 폴더 지정**을 누르고 `G:\내 드라이브` 안의 복사할 폴더를 고른 뒤 수정 권한을 허용합니다. 지정한 폴더는 브라우저가 기억하며, 버튼에 폴더 이름이 표시됩니다.
  2. 파일 행의 **Drive**는 그 파일을, 폴더 행의 **Drive**는 하위 폴더까지 그대로 복사합니다. 포털의 자료는 그대로 남습니다.
  3. 같은 이름·크기의 파일이 이미 있으면 건너뛰고, 이름만 같고 크기가 다르면 `이름 (2).확장자`로 저장합니다.
  4. 클라우드 업로드는 Google Drive 앱이 동기화하며, 동기화 상태는 Drive 앱에서 확인합니다.
  - 브라우저를 다시 열면 첫 복사 때 폴더 접근 허용을 한 번 더 물을 수 있습니다. 다른 PC나 Drive 앱이 없는 PC에서는 사용할 수 없습니다.
- 미리보기: PDF, PNG, JPG, GIF, WebP, 텍스트. Office·HWP 등은 다운로드해서 확인합니다.
- 수정·이동: 폴더 이름 변경·이동(하위 폴더와 파일이 함께 이동), 자료명·소속 폴더 변경(확장자와 파일 내용은 유지).
  - 이동 창 아래쪽 **Google Drive** 영역에서 지정한 Drive 폴더와 그 하위 폴더를 펼쳐 고르면 버튼이 **Drive로 복사**로 바뀌고, 포털 자료는 그대로 둔 채 그 위치에 복사합니다. Drive 폴더를 아직 지정하지 않았으면 그 줄을 눌러 지정합니다.
  - 이동·수정 창의 위치는 탐색기처럼 화살표로 폴더를 펼쳐 고릅니다. 회색으로 표시된 **현재 위치**·**이동할 폴더**는 고를 수 없으며, 아래 **선택한 위치**에서 경로를 확인한 뒤 **이동**(또는 **저장**)을 누릅니다.
- 삭제: 비어 있는 폴더만 삭제할 수 있습니다.
- 우클릭 메뉴: 화면 위쪽에는 **Drive 폴더**와 **자료 등록** 버튼만 있고, 폴더 생성·폴더 업로드·폴더 이름 변경·폴더 이동은 마우스 오른쪽 버튼 메뉴로 씁니다.
  - 빈 곳: 폴더 생성·폴더 업로드·자료 등록, (폴더 안이면) 현재 폴더를 Google Drive로 복사·폴더 이름 변경·폴더 이동, Drive 폴더 지정/변경.
  - 폴더(목록·왼쪽 트리): 열기·하위 폴더 생성·이 폴더에 폴더 업로드·이 폴더에 자료 등록·Google Drive로 복사·폴더 이름 변경·폴더 이동·삭제.
  - 파일: 미리보기·다운로드·Google Drive로 복사·수정·이동·삭제.
  - 조회자에게는 미리보기·다운로드·Google Drive 관련 항목만 표시됩니다.

### 4-6. 자산 관리

- 왼쪽에서 대분류 → 중분류 → 소분류를 만들고, 자산은 소분류를 선택해 등록합니다.
- 일반 비품·IT 장비의 상태·수량·담당자·관리 기한·사전 알림 일수·첨부·변경 이력을 관리합니다.
- 관리 기한 알림은 서버 실행 중 매분 한국 시간 기준으로 확인하며 포털 안에서만 표시합니다(이메일·문자 없음).

### 4-7. TO-DO List

- 빈 공간을 우클릭해 메모를 만들고 바로 입력합니다. 내용은 자동 저장됩니다.
- 완료 체크하면 오른쪽 **완료 보드**로 이동합니다. 작은 메모를 눌러 큰 보기에서 되돌리거나 삭제합니다.

## 6. 백업과 복구

### 6-1. 백업 만들기

- 화면: **설정** → **백업/복구** → **지금 백업**.
- 명령:

```powershell
Set-Location 'F:\ChatGPT\DYKIM-PORTAL'
npm.cmd run backup
Get-ChildItem '.\backups\portal-*.sqlite' | Sort-Object LastWriteTime -Descending | Select-Object -First 3 Name,Length,LastWriteTime
```

- 서버 실행 중에도 백업할 수 있습니다(SQLite 온라인 백업).
- 백업은 매일 자동으로 만듭니다(2026-10-05부터). 포털이 실행 중일 때 1분마다 확인해 마지막 일반 백업이 24시간보다 오래되면 백업하며, 드라이브 여유 공간이 DB 크기의 2배보다 작으면 건너뛰고 로그에 남깁니다(`.env`에 `AUTO_BACKUP=off`이면 끔). 백업의 무결성 검사는 별도 스레드에서 실행해 백업 중에도 포털이 응답합니다. 백업 파일은 단일 파일(SQLite DELETE 저널 방식)로 저장되어 열거나 검사해도 옆에 `-wal`·`-shm` 보조 파일이 생기지 않고, 파일 하나만 복사해도 완전한 백업입니다. 포털 시작 시 예전 백업 옆에 남은 보조 파일(`-wal`, `-shm`, `.partial-wal`, `.partial-shm`)을 정리하고 예전 백업도 단일 파일로 바꿉니다(내용이 남은 `-wal`이 붙은 백업은 건드리지 않음). 다른 디스크·외부 보관은 별도로 해야 합니다. `backups\`의 백업은 생성 후 3일(72시간)이 지나면 자동 삭제되므로, 장기 보관본은 만료 전에 다른 디스크로 복사합니다.
- 백업에는 계정 정보와 모든 첨부파일이 들어 있으므로 공개 장소·일반 채팅·이메일에 올리지 않습니다.
- 실행 중인 `portal.sqlite`를 일반 파일 복사로 백업하지 않습니다.

### 6-2. 화면에서 복구

1. **설정** → **백업/복구** → **복구**에서 시점을 선택하고 파일명을 확인합니다.
2. 포털이 같은 주소로 다시 열리면 완료입니다. 복구 전후 사용자·자료 건수를 확인합니다.
3. 선택한 시점 이후 입력한 내용은 사라집니다.

### 6-3. 수동 복구 (화면 복구를 쓸 수 없을 때)

1. 예약 작업을 중지하고 포트 3000의 포털 프로세스가 없는지 확인합니다.
2. 현재 `data` 폴더 전체를 다른 이름으로 보관합니다.
3. 새 `data` 폴더에 선택한 백업 파일 하나를 `portal.sqlite` 이름으로 놓습니다. 예전 `portal.sqlite-wal`, `portal.sqlite-shm`을 섞지 않습니다.
4. 예약 작업을 시작하고 health, 로그인, 자료 건수를 확인합니다. 문제가 있으면 즉시 중지하고 보관한 `data` 폴더로 되돌립니다.

## 7. 업데이트 절차

1. 6장의 백업을 만들고 파일이 생겼는지 확인합니다.
2. 예약 작업을 중지합니다.
3. 프로젝트 폴더에서 `git pull --ff-only`를 실행합니다. 충돌이 나면 파일을 덮어쓰지 말고 원인을 확인합니다.
4. `package-lock.json`이 바뀌었거나 의존성이 없다는 오류가 나면 `npm.cmd ci`를 실행합니다.
5. `scripts\windows-install.ps1`을 실행하거나 예약 작업을 다시 시작합니다.
6. health와 주요 화면을 확인하고 브라우저에서 **Ctrl + F5**를 누릅니다.

## 8. 장애 대응

### A. 브라우저에서 접속할 수 없음

1. PC 전원과 Windows 로그인 상태를 확인합니다.
2. 2-2의 상태 확인을 실행합니다.
3. 작업이 멈춰 있으면 2-3의 수동 시작을 실행합니다.
4. 계속 실패하면 로그 마지막 부분을 확인합니다: `Get-Content 'F:\ChatGPT\DYKIM-PORTAL\data\server.log' -Tail 50`
5. 의존성이 없다는 메시지가 있으면 `npm.cmd ci` 후 설치 스크립트를 다시 실행합니다.

### B. 포트 3000이 이미 사용 중

```powershell
Get-NetTCPConnection -LocalPort 3000 -State Listen | Select-Object LocalAddress,LocalPort,OwningProcess
Get-CimInstance Win32_Process -Filter 'ProcessId = 12345' | Select-Object ProcessId,Name,ExecutablePath,CommandLine | Format-List
```

- 12345는 위에서 확인한 OwningProcess 번호로 바꿉니다.
- `server/index.mjs` 또는 `server/windows-start.mjs`를 실행하는 이 포털의 `node.exe`일 때만 종료하고 다시 시작합니다. 다른 프로그램은 임의로 종료하지 않습니다.

### C. 작업은 실행 중인데 화면이 오류를 표시함

1. health가 `ok: true`인지 확인합니다.
2. **Ctrl + F5** 후 다시 로그인합니다.
3. 계속되면 2-4 재시작과 B의 포트 점검을 진행하고 `data\server.log`의 오류 시각을 확인합니다.

### D. 로그인 실패, 자료가 비어 보임, “처리 중 오류가 발생했습니다”

- 첫 관리자 화면이 나오거나 자료가 모두 비어 보이면 새 관리자·자료를 입력하지 말고 `.env`의 `DATA_DIR`과 `data\portal.sqlite` 존재 여부를 확인합니다.
- “처리 중 오류가 발생했습니다”는 비밀번호 오류와 다릅니다. `data\server.log`에서 해당 시각 오류를 확인합니다.
- `disk I/O error`가 반복되면 디스크 여유 공간과 상태를 확인하고, 온라인 백업을 만든 뒤 2-4 재시작을 합니다.
- 서버 실행 중인 `portal.sqlite`, `-wal`, `-shm` 파일을 임의로 복사·삭제·교체하지 않습니다.

### E. 파일 등록 실패

- 편집 권한과 디스크 여유 공간(사용량 관리 화면)을 확인합니다.
- 큰 파일은 `data\upload-tmp\` 임시 파일과 SQLite/WAL에 추가 공간이 필요합니다.
- 계속 실패하면 화면의 오류 문구와 `data\server.log`를 함께 확인합니다.

## 9. 저장 공간 관리

- 첨부파일은 모두 `data\portal.sqlite` 안에 저장됩니다. 파일 크기 제한이 없으므로 **사용량 관리**에서 드라이브 여유 공간을 정기적으로 확인합니다.
- 큰 파일은 업로드 중 임시 파일, 데이터베이스, 백업(3일 보관)에 각각 공간을 사용하므로 실제 파일 크기의 몇 배 공간이 필요할 수 있습니다.
- 백업 1개는 데이터베이스와 거의 같은 크기입니다(2026-10-05 기준 약 3.9GB). 매일 자동 백업을 3일 보관하므로 수동 백업을 빼고도 데이터베이스 크기의 3배 이상 공간을 백업 폴더가 사용합니다.
- 큰 파일은 업로드가 끝난 뒤 8MB씩 나누어 데이터베이스에 기록하며 그 사이 다른 요청을 처리하므로 기록 중에도 포털을 계속 사용할 수 있습니다. 기록이 모두 끝나야 목록에 나타나고, 큰 파일 삭제도 기록을 먼저 지운 뒤 백그라운드에서 나누어 정리합니다(2026-10-05 개선). 서버가 도중에 꺼져 기록 없이 남은 조각은 다음 시작 때 정리합니다. 수 GB 파일은 업로드 완료 후 목록에 보일 때까지 몇 분 걸릴 수 있습니다.

## 10. PC 이전 요약

1. 옛 PC에서 입력을 멈추고 `Disable-ScheduledTask`, `Stop-ScheduledTask`로 포털을 중지합니다.
2. `npm.cmd run backup`으로 최종 백업을 만들고 크기·시각을 확인합니다.
3. 새 PC에 Git과 Node.js 24.13 이상 24.x를 설치하고 저장소를 받아 `npm.cmd ci`를 실행합니다.
4. 포털을 시작하기 전에 최종 백업을 새 `data\portal.sqlite`로 복사하고 무결성을 확인합니다.
5. `scripts\windows-install.ps1`로 예약 작업을 등록하고, 기존 관리자 계정으로 로그인해 건수와 첨부파일을 확인합니다.
6. 두 PC를 동시에 사용하지 않습니다(데이터가 자동으로 합쳐지지 않음). 자세한 명령은 PC 이전 가이드(`docs\PC_MIGRATION.md`)를 따릅니다.
